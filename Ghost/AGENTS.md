# 《귀신 상담소》 작업 지침

## 작업 시작 전 필수 절차

이 프로젝트에서 작업을 시작하는 모든 에이전트는, 코드·에셋·씬을 읽거나 수정하기 전에 아래 문서를 **처음부터 끝까지** 읽는다.

1. `Docs/프로젝트-핸드오프.md`
2. `Docs/08-Git-커밋-규칙-및-기록.md`
3. 이 `AGENTS.md`

그 뒤 현재 상태와 문서가 맞는지 확인하기 위해 다음을 확인한다.

- `Assets/Scenes/SampleScene.unity`
- `Assets/GhostCounselor/`
- `Assets/Art/`
- Unity Console 또는 `Logs/Editor.log`의 최근 오류

## 핸드오프 문서 갱신 규칙

기능, 버그, 씬 구조, UI 구조, 아트 적용, 저장 데이터, 검증 결과에 의미 있는 변경이 생기면 작업 완료 전에 `Docs/프로젝트-핸드오프.md`를 갱신한다.

- `현재 상태`는 지금 실제로 작동하는 것만 쓴다.
- `미구현/주의 사항`에는 아직 검증하지 못한 부분을 명확히 쓴다.
- `최근 변경 기록`은 최신 항목을 위에 추가한다.
- 기록이 길어지면 오래된 세부 항목은 `압축 이력` 한두 문장으로 합쳐 문서를 짧게 유지한다.
- 다른 문서와 내용이 겹칠 때는 상세 기획을 복사하지 말고 해당 `Docs/*.md` 파일을 링크한다.

## Git 커밋 및 한글 기록 규칙

- 기능 추가·버그 수정·씬 또는 UI 구조 변경·영구 에셋 추가·중요 기획 변경이 끝나면 작업 완료 전에 Git 커밋을 만든다.
- 커밋 전에는 Play 모드를 끄고 Unity 씬을 저장한다.
- 커밋 메시지는 `feat`, `fix`, `ui`, `art`, `docs`, `chore` 중 목적에 맞는 종류로 시작한다.
- 커밋을 만들 때마다 `Docs/08-Git-커밋-규칙-및-기록.md`의 **커밋 기록** 맨 위에 한글 항목을 추가한다. 항목에는 커밋 해시, 바뀐 점, 주요 파일, 실제 확인 상태를 적는다.
- 테스트하지 못한 내용은 확인했다고 쓰지 않는다. Unity 자동 생성 폴더는 `.gitignore`를 따라 커밋하지 않는다.

## 프로젝트 작업 원칙

- 배경에 클릭·변경되는 UI를 구워 넣지 않는다. 배경, 캐릭터, UI, 인터랙션은 분리한다.
- UI 위치·크기·색은 가능한 한 Unity Hierarchy와 Inspector에서 편집 가능하게 유지한다.
- `Portrait Panel`처럼 디자이너가 씬에서 배치한 UI는 코드가 임의의 좌표로 되돌리지 않는다.
- Unity 컴파일 성공과 Console 오류 0개는 기본 검증이다. 실제 동작은 Play 모드에서 별도로 확인했다고 구분해 기록한다.
- 외부 AI는 보상·엔딩·단서를 임의로 결정하지 않고, 승인된 답변 의도만 반환하도록 유지한다.
